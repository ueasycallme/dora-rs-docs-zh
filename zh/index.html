Dora 用户指南

Dora

Agentic Dataflow-Oriented Robotic Architecture——一个用于构建实时机器人和 AI 应用的 100% Rust 框架。

为什么选择 Dora？

性能

  • 比 ROS2 Python 快 10～17 倍——100% Rust 内核，针对大于 4KB 的消息采用零拷贝共享内存 IPC，从 4KB 到 4MB 的负载延迟保持平稳
  • 原生支持 Apache Arrow——端到端的列式内存格式，无序列化开销；在所有语言绑定之间共享
  • Zenoh SHM 数据平面——节点直接通过 Zenoh 共享内存发布数据，实现零拷贝数据传输；跨机器时自动回退到网络传输
  • 非阻塞事件循环——Zenoh 的发布操作被卸载到 drain 任务中；指标采集在后台运行

开发者体验

  • 单一 CLI，覆盖完整生命周期——本地开发用 dora run，分布式生产环境用 dora up/start，再加上构建、日志、监控、录制 / 回放，全部通过一个工具完成
  • 声明式 YAML 数据流——将管道定义为有向图，通过类型化的输入 / 输出连接节点，可选 类型注解并进行静态校验
  • 多语言节点——使用原生 API（而非封装层）以 Rust、Python、C 或 C++ 编写节点；可在同一数据流中自由混用多种语言
  • 可复用模块——将子图组合为具有类型化输入 / 输出、参数和嵌套组合能力的独立 YAML 文件
  • 热重载——无需重启数据流即可实时重载 Python 算子

生产可用性

  • 容错——按节点设置重启策略（never/on-failure/always）、指数退避、健康监控、带可配置输入超时的断路器
  • 默认分布式——同机节点间使用本地共享内存，跨机通信自动使用 Zenoh 发布 / 订阅，基于 SSH 的集群管理支持按标签调度
  • 协调器高可用——持久化的 redb 状态存储、守护进程自动重连，数据流记录在协调器重启后仍可保留（跨重启完整接管运行中数据流的能力尚不完整，详见相关 tracker）
  • 动态拓扑——通过 CLI 为运行中的数据流添加或移除节点，无需重启
  • 可配置的队列策略——每个输入可选 drop_oldest（默认）或 backpressure，并提供丢弃消息的指标
  • 软实时——可选 --rt 标志启用 mlockall + SCHED_FIFO；支持按节点设置 cpu_affinity 绑核
  • OpenTelemetry——内置结构化日志（支持轮转 / 路由）、指标和分布式追踪

调试与可观测性

  • 录制 / 回放——将数据流消息录制到 .drec 文件，可离线按任意速度回放，并支持节点替换
  • 话题检查——topic echo 打印实时数据，topic hz TUI 用于频率分析，topic info 查看模式与带宽信息
  • 资源监控——dora top TUI 显示所有机器上各节点的 CPU、内存、队列深度、网络 I/O
  • 日志聚合——订阅 dora/logs 即可接收所有节点的结构化日志消息，无需额外接线
  • 追踪检查——trace list 和 trace view 可在无需外部基础设施的情况下查看协调器的 span

生态系统

  • 通信模式——通过常见元数据键内置 服务（请求 / 回复）、动作（目标 / 反馈 / 结果）以及 流式传输（会话 / 分段 / 分块）模式
  • ROS2 桥接——与 ROS2 话题、服务和动作双向互通
  • 进程内算子——在共享运行时内运行的轻量函数，避免按节点启动进程的开销
