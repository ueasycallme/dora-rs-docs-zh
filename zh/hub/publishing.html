Dora 用户指南

发布节点

发布会让你的节点可以通过 hub: <namespace>/<name>@<version> 安装。它不会上传代码：它只是添加一条小小的、仅追加的索引条目，指向你节点源码的某个 git commit。源码仍留在你的仓库中，索引只记录“该节点的版本 X 位于 commit Y，其清单内容如下。”

前置条件

  1. 在节点根目录下提交一个带有 namespace 和 name 的 dora-node.yml。版本不属于清单内容——它会在锚定的 commit 处从 [package].version（Cargo）/ [project].version（pyproject）中读取，或通过 --version 指定。（在清单中添加 version: 会被拒绝——它使用了 deny_unknown_fields。）
  2. 节点源码已推送到某个 git 远程仓库（索引条目会指向它）。
  3. 你的 namespace 与你控制的 GitHub 组织或用户匹配（参见命名空间与所有权）。

预览条目

cd my-node
dora hub publish --dry-run

此命令会解析该 commit，按已提交内容严格校验清单，并打印出将要添加的确切 <namespace>/<name>/<version>.yml 索引条目——不会写入任何内容，也不会打开 PR。请先运行此命令。

常用参数：

标志默认值用途
--rev <ref>HEAD要锚定的 git commit/ref
--repo <url>origin 远程仓库记录在条目中的源仓库 URL
--version <semver>该 commit 处原生清单中的版本覆盖要发布的版本
--index <alias>绑定到你命名空间的索引指定某个具体的 hub.toml 索引
--dry-run—仅校验并打印，不写入

版本、名称和清单都是在锚定的 commit 处读取的（通过 git show <commit>:…），而不是从工作区读取——因此未提交的清单或版本升级会报错，而不会被悄悄发布为条目。请先提交。

发布到官方目录

默认索引是公共目录 dora-rs/dora-hub，一个 git 仓库。因为它以 git 为后端，向它发布就是提交一个拉取请求（pull request）：

dora hub publish        # prints the entry + PR instructions for a git index

针对一个以 git 为后端的索引运行 dora hub publish 会打印出条目内容以及打开一个在 node-index/<namespace>/<name>/<version>.yml 下添加它的 PR 的步骤。随后目录的 CI 会校验该条目（schema、完整 commit 锚定、路径/命名空间一致性、仅追加），由命名空间所有者发起的合规发布会自动合并——发布的延迟就只是 CI 的延迟，和 winget、conda-forge 的模式一样。

版本管理与撤回（yanking）

已发布的版本文件是不可变的——索引是仅追加的。要发布新版本，就添加新条目；要标记某个版本有问题，就撤回（yank）它：

dora hub yank dora-yolo@0.5.1 --reason "panics on empty input"
dora hub yank dora-yolo@0.5.1 --undo        # restore it

撤回只是翻转条目上唯一可变的标志位。被撤回的版本会在新的解析中被跳过（因此 ^0.5 会选取次高的可用版本），但已经锚定该版本的锁文件仍可正常工作，只是会带有警告——所以撤回永远不会破坏已有的可复现构建，它只是阻止新的解析选中它。与发布一样，在以 git 为后端的索引上撤回也只是一个小小的标志位修改 PR。

命名空间与所有权

  • 命名空间（namespace）是一个 GitHub 组织或用户（dora-rs、acme）。索引键是 namespace/name。
  • 一个命名空间只会解析到唯一一个索引（没有搜索顺序，因此不存在依赖混淆问题）。官方的 dora-rs 命名空间始终解析到官方目录。
  • 每个包都带有一份 owners 列表（package.yml）。目录的自动合并仅适用于由包所属命名空间的 owner 发起的常规发布；新建命名空间、owners 变更，或由非 owner 执行的 yank，都会被转入人工审核。新认领的命名空间还必须与认领者的 GitHub 身份匹配（其登录名，或其所属的组织）——认领他人的用户名会被拒绝。
  • std 命名空间及一份简短的保留列表（dora、dora-rs、dora-hub、hub、official 等）均为保留项。

本地索引

若用于测试或磁盘上的私有目录，dora hub publish 针对本地（path =）索引时会直接（原子地，拒绝覆盖已存在的版本）追加条目，而不会打印 PR 说明。配置方法参见自定义与企业索引。

检查清单

dora hub init                      # scaffold dora-node.yml (if you haven't)
dora validate --node-manifest dora-node.yml   # manifest is well-formed
# commit dora-node.yml + the version bump, push
dora hub publish --dry-run         # preview the exact entry
dora hub publish                   # print the entry + PR instructions (or append, for a local index)
