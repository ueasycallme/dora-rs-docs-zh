Node API

from dora import Node

Node 类是自定义节点的主要接口。它连接到正在运行的数据流，接收输入事件并发送输出。

Node 类

__init__(node_id=None)

创建一个新节点并连接到正在运行的数据流。

# Standard: node ID is read from environment variables set by the daemon
node = Node()

# Dynamic: connect to a running dataflow by explicit node ID
node = Node(node_id="my-dynamic-node")

参数：

  • node_id（str，可选）——动态节点的显式节点 ID。省略时，节点会从 dora 守护进程设置的环境变量中读取自身身份。

异常： 若节点无法连接到数据流，将抛出 RuntimeError。

next(timeout=None)

从事件流中获取下一个事件。会阻塞，直到有事件可用或超时。

event = node.next()              # block indefinitely
event = node.next(timeout=2.0)   # block up to 2 seconds

参数：

  • timeout（float，可选）——最长等待时间（秒）。

返回： dict——一个事件字典；若所有发送方均已被丢弃或超时，则返回 None。

drain()

非阻塞地获取所有已缓冲的事件。

events = node.drain()
for event in events:
    print(event["type"])

返回： list[dict]——一个事件字典列表。如果没有缓冲的事件，则返回空列表。

try_recv()

非阻塞接收。如果有可用的事件，返回下一个缓冲的事件。

event = node.try_recv()
if event is not None:
    print(event["type"])

返回： dict | None——一个事件字典；若没有缓冲的事件，则返回 None。

recv_async(timeout=None)

异步接收。供 asyncio 使用。

event = await node.recv_async()
event = await node.recv_async(timeout=5.0)

参数：

  • timeout（float，可选）——最长等待时间（秒）。达到超时时返回错误。

返回： dict | None——一个事件字典；若所有发送方均已被丢弃，则返回 None。

注意： 此方法为实验性功能。pyo3 异步（Rust-Python FFI）集成仍在开发中。

is_empty()

检查事件流中是否有缓冲的事件。

if not node.is_empty():
    event = node.try_recv()

返回： bool

send_output(output_id, data, metadata=None)

在输出通道上发送数据。

import pyarrow as pa

# Send raw bytes
node.send_output("status", b"OK")

# Send an Apache Arrow array (zero-copy capable)
node.send_output("values", pa.array([1, 2, 3]))

# Send with metadata
node.send_output("image", pa.array(pixels), {"camera_id": "front"})

参数：

  • output_id（str）——数据流 YAML 中声明的输出名称。
  • data（bytes | pyarrow.Array）——消息负载。简单数据使用 bytes，零拷贝共享内存传输使用 pyarrow.Array。
  • metadata（dict，可选）——附加在消息上的键值对。支持的值类型：bool、int、float、str、list[int]、list[float]、list[str]、datetime.datetime。

异常： 如果 data 既不是 bytes 也不是 pyarrow.Array，则抛出 RuntimeError。

服务、动作与流式传输模式

Python 节点与 Rust 一样，在通信模式中使用相同的元数据键约定。参数是以字符串为键的普通字典。

常用元数据键：

键描述
"request_id"服务（Service）请求 / 响应关联（UUID v7）
"goal_id"动作（Action）目标标识（UUID v7）
"goal_status"动作结果状态："succeeded"、"aborted" 或 "canceled"
"session_id"流式会话标识符
"segment_id"会话内的流式片段（整数）
"seq"流式数据块的序号（整数）
"fin"流式片段的最后一个数据块（布尔值）
"flush"在输入端丢弃较旧的排队消息（布尔值）

服务客户端示例：

import uuid

# Send a request with a unique request_id
request_id = str(uuid.uuid7())  # Python 3.13+; use uuid_utils or uuid.uuid4() on older versions
node.send_output("request", data, {"request_id": request_id})

服务服务端示例：

# Pass through the metadata (includes request_id) from the incoming request
node.send_output("response", result, event["metadata"])

动作客户端示例：

goal_id = str(uuid.uuid7())
node.send_output("goal", data, {"goal_id": goal_id})

流式示例（用户中断时清空下游队列）：

# `metadata` is a flat dict of parameter name -> value; there is no
# enclosing "parameters" key.
node.send_output(
    "text",
    data,
    metadata={
        "session_id": session_id,
        "segment_id": 1,
        "seq": 0,
        "fin": False,
        "flush": True,
    },
)

完整指南请参见 patterns.md。

日志记录

Python 节点可以使用 Python 内置的 logging 模块（推荐）或显式的节点 API 来记录日志。

Python logging 模块（自动桥接）：

创建 Node() 时，会自动安装一个处理器，将 Python 的 logging 模块路由到 dora 守护进程。无需任何配置：

import logging
from dora import Node

node = Node()  # Installs the logging bridge

logging.info("Sensor initialized")       # -> structured "info" log entry
logging.warning("High temperature")      # -> structured "warn" log entry
logging.debug("Raw bytes: %s", data)     # -> structured "debug" log entry

这些日志条目会连同完整的元数据（级别、消息、文件路径、行号）一起被捕获，并可配合 min_log_level 过滤、send_logs_as 路由以及 dora/logs 订阅者使用。

注意： 不要在创建 Node() 之前调用 logging.basicConfig()。构造函数会设置好桥接；如果先调用 basicConfig()，可能会安装一个冲突的处理器。

显式节点 API：

log(level, message, target=None, fields=None)

发出一条结构化日志消息，可带可选的 target 和键值字段。

node.log("info", "Processing frame", target="vision")
node.log("error", "Sensor timeout", fields={"sensor": "lidar", "retry": "3"})

参数：

  • level (str)——日志级别："error"、"warn"、"info"、"debug" 或 "trace"。
  • message (str)——日志消息。
  • target (str, optional)——目标模块或子系统名称。
  • fields (dict[str, str], optional)——结构化的键值上下文字段。

可配合守护进程的 min_log_level 过滤、send_logs_as 路由以及 dora/logs 订阅者使用。

log_error(message), log_warn(message), log_info(message), log_debug(message), log_trace(message)

常用日志级别的便捷方法：

node.log_error("Connection failed")
node.log_warn("Temperature elevated")
node.log_info("Sensor initialized")
node.log_debug("Raw bytes received")
node.log_trace("Entering loop iteration")

每个方法都等价于 node.log(level, message)。

何时使用哪种方式：

方法是否结构化？是否支持字段？最适用于
logging.info()是否通用日志记录
node.log("info", msg, fields={...})是是结构化上下文（sensor_id 等）
node.log_info(msg)是否快速一行记录
print()否否旧代码、快速调试

dataflow_descriptor()

以 Python 字典形式返回完整的数据流描述文件（已解析的 dataflow YAML）。

descriptor = node.dataflow_descriptor()
print(descriptor["nodes"])

返回： dict

node_config()

从数据流描述文件中返回该节点的配置块。

config = node.node_config()
model_path = config.get("model", "default.pt")

返回： dict

dataflow_id()

返回正在运行的数据流的唯一标识符。

print(node.dataflow_id())  # e.g. "a1b2c3d4-..."

返回： str

is_restart()

检查该节点是否在之前退出或失败后被重启。用于决定是否恢复已保存的状态还是重新开始。

if node.is_restart():
    restore_checkpoint()

返回： bool

restart_count()

返回该节点已被重启的次数。首次运行返回 0，第一次重启后返回 1，依此类推。

print(f"Restart #{node.restart_count()}")

返回： int

merge_external_events(subscription, id=None)

将一个 ROS2 订阅流合并到节点的主事件循环中。调用此方法后，ROS2 消息会作为事件到达，其 kind 设为 "external"，id 设为该订阅的 id（默认为其 ROS2 话题名称）。每个订阅调用一次此方法，即可在一个节点中处理多个话题。

from dora import Node, Ros2Context, Ros2NodeOptions, Ros2QosPolicies

node = Node()
ros2_context = Ros2Context()
ros2_node = ros2_context.new_node("listener", "/", Ros2NodeOptions())
qos = Ros2QosPolicies()
chatter = ros2_node.create_subscription(
    ros2_node.create_topic("/chatter", "std_msgs/String", qos)
)
pose = ros2_node.create_subscription(
    ros2_node.create_topic("/turtle1/pose", "turtlesim/Pose", qos)
)

node.merge_external_events(chatter)            # id defaults to "/chatter"
node.merge_external_events(pose, id="pose")    # or choose your own label

for event in node:
    if event["kind"] == "external":
        print("ROS2", event["id"], event["value"])
    elif event["type"] == "INPUT":
        print("Dora:", event["id"])

参数：

  • subscription (dora.Ros2Subscription)——通过 dora ROS2 桥接创建的 ROS2 订阅。
  • id (str, optional)——来自该订阅的事件标签，以 event["id"] 形式返回。默认为该订阅话题的名称，与传给 create_topic 的名称完全一致（不进行命名空间解析）。不能为空。

迭代支持

Node 类实现了 __iter__ 和 __next__，因此可以直接对其进行迭代：

for event in node:
    match event["type"]:
        case "INPUT":
            process(event["value"])
        case "STOP":
            break

该迭代器在每次迭代时都以不设超时的方式调用 next()。当事件流关闭时，它会返回 None，从而终止循环。

事件字典

事件以普通 Python 字典的形式返回，其结构取决于事件类型。

INPUT

来自另一个节点的输入消息到达。

{
    "type": "INPUT",
    "id": "camera_image",          # input ID as declared in the dataflow YAML
    "kind": "dora",               # "dora" for dataflow events, "external" for ROS2
    "value": <pyarrow.Array>,      # the payload as an Apache Arrow array
    "metadata": {
        "timestamp": datetime,     # UTC-aware datetime.datetime
        "open_telemetry_context": "...",  # tracing context (if enabled)
        ...                        # any user-supplied metadata
    },
}

访问数据：

values = event["value"].to_pylist()     # convert to Python list
array = event["value"].to_numpy()       # convert to NumPy array

INPUT_CLOSED

某个输入通道已关闭（上游节点已结束）。

{
    "type": "INPUT_CLOSED",
    "id": "camera_image",
    "kind": "dora",
}

STOP

数据流正在关闭。

{
    "type": "STOP",
    "id": "MANUAL" | "ALL_INPUTS_CLOSED",   # stop cause
    "kind": "dora",
}

ERROR

运行时中发生了错误。

{
    "type": "ERROR",
    "error": "description of the error",
    "kind": "dora",
}

External（ROS2）

使用 merge_external_events 时，ROS2 消息会以如下形式到达：

{
    "kind": "external",
    "id": "/turtle1/pose",      # the `id` given to merge_external_events, or the topic name
    "value": <pyarrow.Array>,   # the ROS2 message as an Arrow array
}

DoraStatus 枚举

用作算子 on_event 方法的返回值，以控制事件循环。

from dora import DoraStatus
值含义
DoraStatus.CONTINUE继续处理事件（值为 0）
DoraStatus.STOP停止该算子（值为 1）
DoraStatus.STOP_ALL停止整个数据流（值为 2）

算子 API

算子运行在 dora 运行时进程内（不单独起操作系统进程）。它们被定义为一个名为 Operator 的 Python 类，并带有一个 on_event 方法。

Operator 类（用户自定义）

创建一个包含 Operator 类的 Python 文件：

from dora import DoraStatus

class Operator:
    def __init__(self):
        # Initialize state here
        self.count = 0

    def on_event(self, dora_event, send_output) -> DoraStatus:
        if dora_event["type"] == "INPUT":
            self.count += 1
            # Process the input and optionally send output
            send_output("result", b"processed", dora_event["metadata"])
        return DoraStatus.CONTINUE

方法：

  • __init__(self)——算子加载时调用一次。在此初始化状态或模型。
  • on_event(self, dora_event, send_output) -> DoraStatus——每个到来的事件都会调用一次。必须返回一个 DoraStatus 值。

on_event 的参数：

  • dora_event (dict)——一个事件字典。
  • send_output (callable)——用于发送输出数据的回调函数（见下文）。

运行时还会在算子实例上设置 self.dataflow_descriptor，其值为解析后的 dataflow YAML 字典。

send_output 回调

send_output 回调会传给 on_event，用于从算子中发送数据。

send_output(output_id, data, metadata=None)

参数：

  • output_id（str）——数据流 YAML 中声明的输出名称。
  • data (bytes | pyarrow.Array)——数据负载。
  • metadata (dict, optional)——要附加的元数据。传入 dora_event["metadata"] 以传递追踪上下文。

示例：

import pyarrow as pa
from dora import DoraStatus

class Operator:
    def on_event(self, dora_event, send_output) -> DoraStatus:
        if dora_event["type"] == "INPUT":
            result = pa.array([42], type=pa.int64())
            send_output("output", result, dora_event["metadata"])
        return DoraStatus.CONTINUE

DataflowBuilder

from dora.builder import DataflowBuilder, Node, Operator, Output

以编程方式构建 dataflow YAML。

DataflowBuilder 类

__init__(name="dora-dataflow")

创建一个新的数据流构建器。

flow = DataflowBuilder("my-robot")

参数：

  • name (str, optional)——数据流的名称，默认为 "dora-dataflow"。

add_node(id, **kwargs) -> Node

向数据流添加一个节点。返回一个 Node 对象以供进一步配置。

sender = flow.add_node("sender")

参数：

  • id (str)——唯一的节点标识符。
  • **kwargs——传递给 YAML 的额外节点配置。

返回： Node（构建器）

to_yaml(path=None) -> str | None

生成数据流的 YAML 表示。若指定了 path，则写入文件并返回 None；否则返回 YAML 字符串。

# Write to file
flow.to_yaml("dataflow.yml")

# Get as string
yaml_str = flow.to_yaml()

参数：

  • path (str, optional)——写入 YAML 的文件路径。

返回： str | None

上下文管理器

DataflowBuilder 支持 with 语句：

with DataflowBuilder("my-flow") as flow:
    flow.add_node("sender").path("sender.py")
    flow.to_yaml("dataflow.yml")

Node 类（构建器）

由 DataflowBuilder.add_node() 返回。所有 setter 方法都返回 self 以支持链式调用。

path(path) -> Node

设置节点可执行文件或脚本的路径。

node.path("my_node.py")

args(args) -> Node

设置节点的命令行参数。

node.args("--verbose --port 8080")

env(env) -> Node

设置节点的环境变量。

node.env({"MODEL_PATH": "/models/yolo.pt"})

build(command) -> Node

设置节点的构建命令（在启动前运行）。

node.build("pip install -r requirements.txt")

git(url, branch=None, tag=None, rev=None) -> Node

将一个 Git 仓库设为节点的来源。

node.git("https://github.com/org/repo.git", branch="main")

add_operator(operator) -> Node

为此节点附加一个 Operator。

op = Operator("detector", python="object_detection.py")
node.add_operator(op)

add_output(output_id) -> Output

在此节点上声明一个输出，并返回一个 Output 引用，供作为输入来源使用。

output = sender.add_output("data")

add_input(input_id, source, queue_size=None, queue_policy=None) -> Node

将此节点订阅到另一个节点的输出。

# Using an Output object
output = sender.add_output("data")
receiver.add_input("data", output)

# Using a string reference
receiver.add_input("tick", "dora/timer/millis/100")

# With a custom queue size
receiver.add_input("images", camera_output, queue_size=2)

# Lossless input (blocks sender when full)
receiver.add_input("commands", cmd_output, queue_size=100, queue_policy="backpressure")

参数：

  • input_id (str)——此节点上输入的名称。
  • source (str | Output)——可以是字符串（"node_id/output_id"）或一个 Output 对象。
  • queue_size (int, optional)——此输入缓冲消息的最大数量。
  • queue_policy (str, optional)——"drop_oldest"（默认）或 "backpressure"（在丢弃前最多缓冲 10 倍 queue_size）。

to_dict() -> dict

返回该节点用于 YAML 序列化的字典表示。

Output 类（构建器）

由 Node.add_output() 返回。表示对节点输出的引用，用作 add_input() 中的来源。

output = sender.add_output("data")
receiver.add_input("sensor_data", output)
str(output)  # "sender/data"

Operator 类（构建器）

定义一个用于嵌入节点 YAML 配置中的算子。

__init__(id, name=None, description=None, build=None, python=None, shared_library=None, send_stdout_as=None)

op = Operator(
    id="detector",
    python="object_detection.py",
    send_stdout_as="detection_text",
)

参数：

  • id (str)——唯一的算子标识符。
  • name (str, optional)——显示名称。
  • description (str, optional)——人类可读的描述。
  • build (str, optional)——加载前运行的构建命令。
  • python (str, optional)——Python 算子文件的路径。
  • shared_library (str, optional)——共享库算子的路径。
  • send_stdout_as (str, optional)——将算子的 stdout 路由为具有此 ID 的输出。

to_dict() -> dict

返回用于 YAML 序列化的字典表示。

CUDA 模块（可选扩展）

不属于 1.0 API。这些辅助函数在 1.0 之前已从 dora 包移出到 dora_tensor_pool 扩展中——它们的存在是为了服务于位于扩展接缝之外的张量池传输，不受 dora 1.0 兼容性保证的覆盖。请从 libraries/extensions/tensor-pool/python 安装。

from dora_tensor_pool import torch_to_ipc_buffer, ipc_buffer_to_ipc_handle, open_ipc_handle

用于在节点之间通过 CUDA IPC 实现 GPU 张量零拷贝共享的工具。需要支持 CUDA 的 PyTorch 和支持 CUDA 的 Numba。

torch_to_ipc_buffer(tensor) -> tuple[pyarrow.Array, dict]

将一个 PyTorch CUDA 张量转换为包含 CUDA IPC handle 的 Arrow 数组，以及一个元数据字典。将两者一起通过数据流发送，即可在不拷贝的情况下共享 GPU 内存。

import torch
import pyarrow as pa
from dora import Node
from dora_tensor_pool import torch_to_ipc_buffer

node = Node()
tensor = torch.randn(1024, 768, device="cuda")
ipc_buffer, metadata = torch_to_ipc_buffer(tensor)
node.send_output("gpu_data", ipc_buffer, metadata)

参数：

  • tensor (torch.Tensor)——一个 CUDA 张量。

返回： tuple[pyarrow.Array, dict]——以 int8 Arrow 数组形式表示的 IPC handle，以及包含 shape、strides、dtype、size、offset 和来源信息的元数据。

ipc_buffer_to_ipc_handle(handle_buffer, metadata) -> IpcHandle

从接收到的 Arrow 缓冲区和元数据重建一个 CUDA IPC handle。

from dora_tensor_pool import ipc_buffer_to_ipc_handle

event = node.next()
ipc_handle = ipc_buffer_to_ipc_handle(event["value"], event["metadata"])

参数：

  • handle_buffer (pyarrow.Array)——来自 event["value"] 的 Arrow 数组。
  • metadata (dict)——来自 event["metadata"] 的元数据。

返回： dora_tensor_pool.IpcHandle（一个围绕 cudaIpcMemHandle_t 的轻量封装；调用 .open() 将该 handle 映射到当前进程并获得设备指针，调用 .close() 释放它）。

open_ipc_handle(ipc_handle, metadata) -> ContextManager[torch.Tensor]

打开一个 CUDA IPC handle 并生成一个 PyTorch 张量。请作为上下文管理器使用，以确保正确清理。

from dora_tensor_pool import ipc_buffer_to_ipc_handle, open_ipc_handle

event = node.next()
ipc_handle = ipc_buffer_to_ipc_handle(event["value"], event["metadata"])

with open_ipc_handle(ipc_handle, event["metadata"]) as tensor:
    result = tensor * 2  # use the GPU tensor directly

参数：

  • ipc_handle (IpcHandle)——来自 ipc_buffer_to_ipc_handle 的 handle。
  • metadata (dict)——包含 shape、strides 和 dtype 信息的元数据字典。

返回： 生成 CUDA 上的 torch.Tensor 的上下文管理器。

快速开始示例

一个完整的节点，用于接收图像、处理图像并发送结果：

#!/usr/bin/env python3
"""Example node: receives messages, transforms them, and sends output."""

import logging

import pyarrow as pa
from dora import Node


def main():
    node = Node()

    for event in node:
        if event["type"] == "INPUT":
            input_id = event["id"]

            if input_id == "message":
                values = event["value"].to_pylist()
                number = values[0]

                # Create a struct array with multiple fields
                result = pa.StructArray.from_arrays(
                    [
                        pa.array([number * 2]),
                        pa.array([f"Message #{number}"]),
                    ],
                    names=["doubled", "description"],
                )
                node.send_output("transformed", result)
                logging.info("Transformed message %d", number)

        elif event["type"] == "STOP":
            logging.info("Node stopping")
            break


if __name__ == "__main__":
    main()

运行方式：

dora run dataflow.yml

DataflowBuilder 示例

以编程方式构建数据流，而不是手写 YAML：

#!/usr/bin/env python3
"""Build a simple sender -> receiver dataflow."""

from dora.builder import DataflowBuilder, Operator

flow = DataflowBuilder("example-flow")

# Add a timer-driven sender node
sender = flow.add_node("sender")
sender.path("sender.py")
tick_output = sender.add_output("message")

# Add a receiver that subscribes to the sender
receiver = flow.add_node("receiver")
receiver.path("receiver.py")
receiver.add_input("message", tick_output)

# Add a node with a timer input
timed_node = flow.add_node("periodic")
timed_node.path("periodic.py")
timed_node.add_input("tick", "dora/timer/millis/100")

# Add a node with an operator
runtime_node = flow.add_node("runtime-node")
op = Operator("detector", python="object_detection.py")
runtime_node.add_operator(op)
runtime_node.add_input("image", "camera/image")

# Write or print the YAML
flow.to_yaml("dataflow.yml")
print(flow.to_yaml())
