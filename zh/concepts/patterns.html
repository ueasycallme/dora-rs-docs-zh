Dora 用户指南

通信模式

Dora 是一个基于发布 / 订阅消息传递的数据流框架。在基础话题之上，该框架通过一组约定的元数据键支持 服务（Service）（请求 / 回复）、动作（Action）（目标 / 反馈 / 结果）以及 流式传输（streaming）（会话 / 分段 / 分块）模式。这些模式是在节点 API 层面以约定方式实现的，无需对守护进程、协调器或 YAML 语法做任何改动。

1. 话题（发布 / 订阅）

默认模式。节点在输出上发布数据，任何订阅该输出的节点都会收到数据。

nodes:
  - id: publisher
    outputs:
      - data
  - id: subscriber
    inputs:
      data: publisher/data

适用场景：流式传感器数据、周期性状态、即发即弃的事件。

2. 服务（请求 / 回复）

客户端发送一个请求，并期望收到恰好一个响应，二者通过 request_id 元数据键关联。

常用元数据键

键常量描述
request_iddora_node_api::REQUEST_ID用于关联请求和响应的 UUID v7

YAML

nodes:
  - id: client
    inputs:
      tick: dora/timer/millis/500
      response: server/response
    outputs:
      - request

  - id: server
    inputs:
      request: client/request
    outputs:
      - response

节点 API 辅助函数

#![allow(unused)]
fn main() {
// Client: send request with auto-generated request_id
let rid = node.send_service_request("request".into(), params, data)?;

// Server: pass through metadata.parameters (includes request_id)
node.send_service_response("response".into(), metadata.parameters, result)?;
}

服务端必须将收到请求的元数据参数中的 request_id 原样传递到响应中。客户端通过该键将响应与请求进行匹配。

示例：examples/service-example/

3. 动作（目标 / 反馈 / 结果）

客户端发送一个目标，并收到周期性反馈以及最终结果。动作支持取消。

常用元数据键

键常量描述
goal_iddora_node_api::GOAL_ID标识该目标的 UUID v7
goal_statusdora_node_api::GOAL_STATUS目标的最终状态

目标状态取值：

值常量含义
succeededGOAL_STATUS_SUCCEEDED目标成功完成
abortedGOAL_STATUS_ABORTED目标被服务端中止
canceledGOAL_STATUS_CANCELED目标被客户端取消

YAML

nodes:
  - id: client
    inputs:
      tick: dora/timer/millis/2000
      feedback: server/feedback
      result: server/result
    outputs:
      - goal
      - cancel

  - id: server
    inputs:
      goal: client/goal
      cancel: client/cancel
    outputs:
      - feedback
      - result

取消模式

客户端在 cancel 输出上发送一条消息，并在元数据中携带 goal_id。服务端会在各处理步骤之间检查是否存在取消请求，并发送 goal_status = "canceled" 的结果。

示例：examples/action-example/

4. 流式传输（会话 / 分段 / 分块）

适用于用户可在流中途打断且已排队数据必须被丢弃的实时管道（语音、视频、传感器流）。

常用元数据键

键类型常量描述
session_id字符串SESSION_ID标识对话 / 会话
segment_id整数SEGMENT_ID会话内的逻辑单元（例如一句话）
seq整数SEQ分段内的分块序号
fin布尔值FIN分段最后一个分块时为 true
flush布尔值FLUSH设为 true 以丢弃该输入上更早排队的消息

YAML

nodes:
  - id: asr
    inputs:
      mic: mic-source/audio
    outputs:
      - text

  - id: llm
    inputs:
      text: asr/text
    outputs:
      - tokens

  - id: tts
    inputs:
      tokens: llm/tokens
    outputs:
      - audio

Node API

#![allow(unused)]
fn main() {
use dora_node_api::{StreamSegment, DoraNode};

let mut seg = StreamSegment::new();

// Send chunks with auto-incrementing seq (e.g. inside an ASR node)
node.send_stream_chunk("text".into(), &mut seg, false, chunk_data)?;
// Mark final chunk of a segment
node.send_stream_chunk("text".into(), &mut seg, true, last_chunk)?;

// On user interruption: flush downstream queues and start a new segment.
// The prior segment ends without a fin=true signal -- old data is discarded.
let flush_params = seg.flush();
node.send_output("text".into(), flush_params, empty_data)?;
}

队列清空行为

当一条元数据中带有 flush: true 的消息到达时，在该 flush 消息被投递之前，接收方的输入队列会被清空所有更早的消息。这使语音管道可以实现即时打断——当用户在 TTS 输出过程中开口说话时，ASR 节点会发送一个带有 flush: true 的新分段，TTS 节点便会立即丢弃上一次响应中任何已排队的音频分块。

注意：flush 会丢弃该输入上所有排队消息，而不区分 session_id。使用 flush 时，不要在单个输入上复用多个独立会话。

Python

# `metadata` is a flat dict of parameter name -> value; there is no
# enclosing "parameters" key.
node.send_output(
    "text",
    data,
    metadata={
        "session_id": session_id,
        "segment_id": 1,
        "seq": 0,
        "fin": False,
        "flush": True,  # flush older queued messages
    },
)

5. 选择合适的模式

需要响应吗？是否长时间运行？可取消吗？实时流吗？模式
否--否话题
是否否否服务
是是可选否动作
否是通过 flush是流式传输

6. 重要细节

  • goal_status 的匹配区分大小写。 请始终使用精确的小写取值："succeeded"、"aborted"、"canceled"。对于无法识别的取值，ROS2 桥接默认使用 Aborted。

7. Python 兼容性

Python 节点使用相同的元数据约定。参数是以字符串为键的普通字典：

# Service client -- `send_service_request` generates the request_id (uuid7,
# time-ordered, matching the Rust API) and returns it to correlate on.
request_id = node.send_service_request("request", data)

# Service server -- echo the request's metadata back, which carries request_id
node.send_service_response("response", result, metadata=event["metadata"])

metadata 是一个参数名 -> 值的扁平字典，与接收端 event["metadata"] 的结构相同。如果再用一层外包的 {"parameters": ...} 键将其包裹，不会明显报错：该字典不是受支持的参数类型，于是会被强制转换为其字符串表示形式，并放到一个字面名为 parameters 的参数下（同时发出警告），而关联键则永远不会到达。

如果你需要在发送前就获取该 id——或者没有使用服务辅助函数——请自行设置它，并保持扁平结构：

import uuid

request_id = str(uuid.uuid7())
node.send_output("request", data, metadata={"request_id": request_id})

注意：uuid.uuid7() 需要 Python 3.13+。在旧版本上，请使用 uuid_utils 包或 uuid.uuid4()（随机 v4 也可用于关联，但会失去时间顺序性）。
