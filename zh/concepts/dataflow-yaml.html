Dora 用户指南

Dataflow YAML 规范

数据流在 YAML 文件中定义。每个文件描述一个节点图，以及节点的输入/输出和执行参数。

仓库根目录提供了一个 JSON Schema（dora-schema.json），可用于编辑器自动补全和校验。

快速开始

nodes:
  - id: sender
    path: sender.py
    outputs:
      - message

  - id: receiver
    path: receiver.py
    inputs:
      message: sender/message

使用 dora run dataflow.yml（本地模式）或 dora up && dora start dataflow.yml（网络模式）运行。

编辑器设置

在 YAML 文件顶部添加 schema 注释以启用 VS Code 自动补全（需要安装 YAML 扩展）：

# yaml-language-server: $schema=https://raw.githubusercontent.com/dora-rs/dora/main/dora-schema.json
nodes:
  - id: my-node
    # ... autocompletion works here

根级字段

字段类型默认值描述
nodeslist必需节点配置列表
strict_typesboolfalse在 validate 和 build 中将类型警告视为错误
type_ruleslist[]用户定义的类型兼容性规则（参见 类型注解）
health_check_intervalfloat5.0守护进程健康检查扫描之间的间隔秒数。对于设置了 health_check_timeout 的每个节点，守护进程会检查该节点是否在其超时时间内进行过通信；如果没有，该节点将被终止，并评估其 restart_policy
deployobject–根级部署配置（参见 Deployment）
debugobject–调试选项（参见 Debug）

节点配置

每个节点都需要一个 id。其他字段均为可选（不过大多数节点至少需要 path 或 operator/operators）。

标识

字段类型描述
idstring必需。唯一标识符。不能包含 /。不建议使用空白字符
namestring人类可读的显示名称（仅作为元数据，用于工具和日志）
descriptionstring文档字符串（仅作为元数据，运行时不使用）

Source

节点的可执行文件可以来自本地路径、Git 仓库、模块引用，或者是隐式的（算子/ROS2 节点）。

字段类型描述
pathstring可执行文件或脚本的路径。也可以是 URL（遗留用法）
modulestring模块定义文件的路径（与 path 互斥）。参见 模块指南
gitstringGit 仓库 URL。dora build 会克隆该仓库，并将克隆目录用作工作目录
branchstring要检出的分支（需要 git，与 tag/rev 互斥）
tagstring要检出的标签（需要 git，与 branch/rev 互斥）
revstring要检出的 commit hash（需要 git，与 branch/tag 互斥）
buildstring在 dora build 期间运行的构建命令。每一行单独运行。使用 --uv 时，pip/pip3 行会使用 uv pip，并且 Python 节点会在 <working-dir>/.dora/python-envs/<node-id>/ 获得一个专用的受管 venv，运行时会在启动时重用该 venv。详情参见 CLI 参考。
argsstring命令行参数（以空格分隔）

使用 Git 源的示例：

- id: rust-node
  git: https://github.com/dora-rs/dora.git
  branch: main
  build: cargo build -p example-node --release
  path: target/release/example-node

数据 I/O

输入

输入使用 <node-id>/<output-id> 格式订阅另一个节点的输出：

inputs:
  # Short form
  image: camera/frames
  tick: dora/timer/millis/100

  # Long form with options
  sensor_data:
    source: sensor/frames
    queue_size: 10
    queue_policy: drop_oldest
    input_timeout: 5.0

  # Lossless input (blocks sender when full)
  commands:
    source: controller/cmd
    queue_size: 100
    queue_policy: backpressure
输入选项类型默认值描述
sourcestring必需<node-id>/<output-id> 或定时器路径
queue_sizeinteger10输入缓冲区大小
queue_policystringdrop_oldestdrop_oldest：缓冲区满时丢弃最旧的消息。backpressure：最多缓冲 queue_size 的 10 倍而不丢弃（达到硬上限时会丢弃并记录 ERROR 日志）
input_timeoutfloat–断路器超时时间（秒）。如果在此时间段内没有消息到达，守护进程会关闭该输入，节点会收到一个 InputClosed 事件以实现优雅降级

内置定时器

定时器是以固定间隔发出 tick 的虚拟节点：

inputs:
  tick: dora/timer/millis/100   # every 100ms
  slow: dora/timer/millis/1000  # every 1s
  fast: dora/timer/hz/30        # 30 Hz (~33ms)

内置日志聚合

订阅来自所有（或经过筛选的）节点的结构化日志消息：

inputs:
  all_logs: dora/logs               # all nodes, all levels
  errors:   dora/logs/error         # error+ from all nodes
  sensor:   dora/logs/info/sensor   # info+ from specific node

每条消息以 JSON 编码的 LogMessage 字符串形式到达。详情参见 日志记录。

输出

节点产生的输出标识符列表：

outputs:
  - processed_image
  - metadata

类型注解

输入和输出的可选类型注解。类型从不是必需的——未注解的端口将保持完全动态。

- id: camera
  path: camera.py
  outputs:
    - image
    - depth
  output_types:
    image: std/media/v1/Image
    depth: std/media/v1/Image

- id: detector
  path: detect.py
  inputs:
    image: camera/image
  input_types:
    image: std/media/v1/Image
  outputs:
    - bbox
  output_types:
    bbox: std/vision/v1/BoundingBox
字段类型默认值描述
output_typesobject{}将输出 ID 映射到类型 URN。键必须与 outputs 中的条目匹配
input_typesobject{}将输入 ID 映射到期望的类型 URN。键必须与 inputs 中的条目匹配
output_metadataobject{}将输出 ID 映射到所需元数据键的列表
patternstring–通信模式简写：service-server、service-client、action-server、action-client

类型 URN 使用 std/<category>/v<version>/<TypeName> 格式，并支持参数（例如 std/media/v1/AudioFrame[sample_type=f32]）。完整的标准类型库、参数化类型、兼容性规则和用户自定义类型请参见类型注解指南。

运行 dora validate <file> 可静态检查类型注解。如需运行时检查，设置 DORA_RUNTIME_TYPE_CHECK=warn 或 error：

dora validate dataflow.yml
DORA_RUNTIME_TYPE_CHECK=warn dora run dataflow.yml

若有注解，类型也会显示在 dora graph 的边标签上。

Arrow IPC 分帧

按输出覆盖的传输分帧方式。默认为 raw（Arrow 缓冲区布局）。设为 arrow-ipc 可使用自描述的 Arrow IPC 流格式。

字段类型默认值描述
output_framing映射{}按输出的分帧方式：raw（默认）或 arrow-ipc
 
- id: sensor
  path: ./sensor
  outputs:
    - image
  output_framing:
    image: arrow-ipc

模块参数

使用 module: 时，通过 params: 传递配置值：

- id: fast_pipeline
  module: modules/transform.module.yml
  inputs:
    data: sender/value
  params:
    speed: "2.0"
    mode: turbo

在模块内部，参数可在 args: 中以 $PARAM_<UPPERCASE_KEY> 的形式访问，也可作为环境变量使用。完整文档请参见模块指南。

环境

env:
  MY_VAR: "value"          # string
  DEBUG: true               # boolean
  PORT: 8080                # integer
  RATE: 1.5                 # float
  FROM_HOST:
    __dora_env: HOST_VAR   # read from host environment at runtime

环境变量同时适用于 build 命令和节点执行。取值支持 $VAR 展开语法。

日志记录

字段类型默认值描述
send_stdout_asstring–将原始 stdout/stderr 行作为数据输出路由。每一行作为一条独立的 Arrow 消息发送
send_logs_asstring–将结构化日志条目作为数据输出路由。每条记录是一个 JSON 字符串，包含字段：timestamp、level、node_id、message、target、fields
min_log_levelstring–抑制低于此级别的日志，不写入文件输出、不转发给协调器，也不通过 send_logs_as 发送。级别从最详细到最简略依次为：stdout（包括原始 stdout 的全部输出）、trace、debug、info、warn、error
max_log_sizestring–日志文件达到此大小后进行轮转（例如 "50MB"、"1GB"）
max_rotated_filesinteger5保留的轮转日志文件数量

示例：

- id: sensor
  path: ./sensor
  min_log_level: info
  send_stdout_as: raw_output
  send_logs_as: log_entries
  max_log_size: "100MB"
  max_rotated_files: 3
  outputs:
    - data
    - raw_output
    - log_entries

使用 send_stdout_as 或 send_logs_as 时，请将该输出名称加入 outputs 列表，以便下游节点可以订阅它。

有关所有日志功能的完整指南，请参见日志。

容错

字段类型默认值描述
restart_policystringnevernever、on-failure 或 always
max_restartsinteger0最大重启尝试次数。0 表示无限制
restart_delayfloat–初始退避时间（秒）。每次尝试翻倍
max_restart_delayfloat–指数退避的上限
restart_windowfloat–统计重启次数的时间窗口。自当前窗口内首次重启起经过这么多秒后，计数器会重置。可与 max_restarts 配合实现“每 M 秒最多 N 次重启”的语义
health_check_timeoutfloat–一旦节点已连接（已订阅事件），若之后在这么多秒内未与守护进程通信（发送输出、确认 tick 等），守护进程会终止该进程并评估 restart_policy。仅覆盖连接后的存活检测
startup_timeoutfloat–若节点进程在启动后这么多秒内未能连接（订阅事件），守护进程会终止该进程并评估 restart_policy。用于限定启动/初始化时间。在每次 health_check_interval（默认 5 秒）触发时进行评估

重启策略：

  • never（默认）：不自动重启
  • on-failure：仅在退出码非零时重启
  • always：任何退出都重启，除非是用户停止或所有输入成功关闭的情况

带指数退避的示例：

- id: sensor
  path: ./sensor
  restart_policy: on-failure
  max_restarts: 5
  restart_delay: 1.0         # 1s, 2s, 4s, 8s, 16s
  max_restart_delay: 30.0    # capped at 30s
  restart_window: 300.0      # 5 restarts per 5 minutes
  health_check_timeout: 30.0

部署

使用 deploy 将节点分配到特定机器：

- id: camera-driver
  deploy:
    machine: robot-arm
  path: ./target/debug/camera
  outputs:
    - frames

- id: ml-inference
  deploy:
    machine: gpu-server
    labels:
      gpu: "true"
    distribute: scp
  path: ./target/debug/inference
  inputs:
    frames: camera-driver/frames
Deploy 字段类型默认值描述
machinestring–目标机器/守护进程 ID。协调器会将节点路由到以此 ID 注册的守护进程
working_dirstring–目标机器上的工作目录
labelsobject–用于调度的键值标签。协调器会将这些标签与每个守护进程在注册时上报的标签进行匹配
distributestringlocal已构建的二进制文件如何送达目标守护进程：local——每个守护进程独立从源码构建；scp——CLI 在启动前通过 SSH/SCP 推送已构建的二进制文件；http——守护进程从协调器的 HTTP 工件存储中拉取二进制文件

当节点位于不同机器上时，通信会自动从共享内存切换到 Zenoh pub/sub。

CPU 亲和性

将节点的进程固定到特定的 CPU 核心（仅限 Linux）。

字段类型默认值描述
cpu_affinityint 列表–要将节点进程固定到的 CPU 核心索引
 
- id: controller
  path: ./controller
  cpu_affinity: [0, 1]

算子节点

算子在共享运行时内进程内运行（没有独立进程）。单个算子使用 operator，多个算子使用 operators。

单个算子

对于单个算子，id 字段是可选的（默认为节点的 id）：

- id: detector
  operator:
    python: detect.py
    build: pip install -r requirements.txt
    inputs:
      image: camera/frames
    outputs:
      - bbox

operators 列表

operators 是 operator 的列表形式。其每个条目必须有一个 id，该 ID 会成为对其输出的每次引用的一部分（<node>/<operator>/<output>）。

一个运行时节点只能持有一个算子：算子运行时在零个或多个算子的情况下都会拒绝启动，因此校验会拒绝这样的节点。要运行多个算子，请为每个算子分配各自的节点：

- id: preprocess
  operators:
    - id: preprocessor
      shared-library: ../../target/debug/libpreprocess
      inputs:
        raw: sensor/data
      outputs:
        - processed
- id: analyze
  operators:
    - id: analyzer
      shared-library: ../../target/debug/libanalyze
      inputs:
        data: preprocess/preprocessor/processed
      outputs:
        - result

算子源类型

字段描述
pythonPython 脚本路径，或 {source: "script.py", conda_env: "myenv"}
shared-library共享库路径（.so/.dylib/.dll）

算子同样支持 inputs、outputs、build、send_stdout_as、send_logs_as、min_log_level、max_log_size 和 max_rotated_files，语义与节点级字段相同。

ROS2 桥接

将节点声明为 ROS2 桥接，可自动在 ROS2 消息与 Dora 的 Arrow 格式之间转换。默认使用 DDS；原生 rmw_zenoh_cpp 兼容性需显式选择。

ros2:
  transport:
    kind: zenoh
    compatibility: humble # or rep2016
    config_uri: /etc/zenoh/session.json5 # optional
  topic: /chatter
  message_type: std_msgs/String
  direction: subscribe

config_uri 会覆盖 ZENOH_SESSION_CONFIG_URI；否则使用内置的 Zenoh 默认配置。所选 profile 和 ROS_DOMAIN_ID 必须与 ROS 对端一致。

单个话题

- id: camera_bridge
  ros2:
    topic: /camera/image_raw
    message_type: sensor_msgs/Image
    direction: subscribe
  outputs:
    - image

多个话题

- id: robot_bridge
  ros2:
    topics:
      - topic: /camera/image_raw
        message_type: sensor_msgs/Image
        direction: subscribe
        output: image
      - topic: /cmd_vel
        message_type: geometry_msgs/Twist
        direction: publish
        input: velocity
    qos:
      reliable: true
  inputs:
    velocity: planner/cmd_vel
  outputs:
    - image

服务（Service）桥接

- id: add_service
  ros2:
    service: /add_two_ints
    service_type: example_interfaces/AddTwoInts
    role: server
  inputs:
    request: client_node/request
  outputs:
    - response

动作（Action）桥接

- id: nav_action
  ros2:
    action: /navigate
    action_type: nav2_msgs/NavigateToPose
    role: client
  inputs:
    goal: planner/goal
  outputs:
    - feedback
    - result

QoS 配置

QoS 可以在桥接级别设置（适用于所有话题），也可以按话题设置：

QoS 字段类型默认值描述
reliableboolfalse可靠传输还是尽力传输
durabilitystringvolatilevolatile 或 transient_local
livelinessstringautomaticautomatic, manual_by_participant, manual_by_topic
lease_durationfloat无限租约时长（秒）
max_blocking_timefloat–可靠传输的最大阻塞时间
keep_lastinteger1历史深度（KeepLast 策略）
keep_allboolfalse使用 KeepAll 历史策略而非 KeepLast

字段类型默认值描述

debug:

通信模式

Dora 支持在数据流之上构建的四种通信模式：

  • Topic（默认）：发布/订阅式数据流
  • 服务（Service）：通过 request_id 元数据实现请求 / 回复
  • 动作（Action）：通过 goal_id / goal_status 元数据实现目标 / 反馈 / 结果，并支持取消
  • Streaming：通过 session_id/segment_id/seq/fin/flush 元数据实现会话/分段/分块，并支持通过队列刷新实现中断

详情和示例见通信模式。

完整示例

health_check_interval: 10.0

debug:
  enable_debug_inspection: true

nodes:
  - id: webcam
    operator:
      python: webcam.py
      inputs:
        tick: dora/timer/millis/100
      outputs:
        - image

  - id: detector
    operator:
      python: detect.py
      build: pip install ultralytics
      inputs:
        image: webcam/image
      outputs:
        - bbox

  - id: plotter
    operator:
      python: plot.py
      inputs:
        image: webcam/image
        bbox: detector/bbox

  - id: logger
    path: ./logger
    inputs:
      bbox: detector/bbox
    send_stdout_as: logs
    min_log_level: info
    restart_policy: on-failure
    max_restarts: 3
    outputs:
      - logs
