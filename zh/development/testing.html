Dora 用户指南

Dora 测试指南

本指南介绍了如何在 Dora 工作区中运行、编写和排查测试问题。

快速开始（5 分钟验证）

运行以下三条命令以验证工作区是否正常：

# 1. Format check (~5s)
cargo fmt --all -- --check

# 2. Lint (~60s first run, cached after)
cargo clippy --all \
  --exclude dora-node-api-python \
  --exclude dora-operator-api-python \
  --exclude dora-ros2-bridge-python \
  -- -D warnings

# 3. Unit + integration tests (~90s first run)
cargo test --all \
  --exclude dora-runtime-python \
  --exclude dora-node-api-python \
  --exclude dora-operator-api-python \
  --exclude dora-ros2-bridge-python

开 PR 前这三条都必须通过。Python 包不包含在内，因为它们需要 maturin。

测试层级

层级覆盖范围命令速度
Format代码风格cargo fmt --all -- --check~5s
Lint警告、正确性cargo clippy --all ...~60s
Unit单个函数cargo test --all ...~90s
CLI命令解析、校验cargo test -p dora-cli~5s
Integration通过环境变量实现的节点 I/Ocargo test --test example-tests~30s
Smoke完整的 CLI 生命周期cargo test --test example-smoke -- --test-threads=1约 3 分钟
E2E多数据流场景cargo test --test ws-cli-e2e -- --ignored --test-threads=1约 2 分钟
容错重启策略、超时cargo test --test fault-tolerance-e2e~45s
Typos拼写安装 typos-cli，然后运行 typos~2s

层级详情

单元测试

单元测试通过 #[cfg(test)] 模块与被测代码放在一起。包含测试的关键 crate 有：

Crate测试数量测试内容
dora-arrow-convert~26Arrow 类型的往返转换
dora-cli~96命令解析、值解析器、日志 grep/过滤、JSON 解析、WebSocket 客户端、集群配置
dora-coordinator~24WS 控制/守护进程平面、健康检查、并发请求、工件存储、速率限制器、错误净化
dora-coordinator-store~10内存与 redb 的 CRUD、模式版本管理、持久化
dora-core~8数据流描述文件校验
dora-daemon~2Shlex 参数解析
dora-node-api~10输入跟踪、服务（service）/动作（action）辅助函数（ID 生成、send_service_request/response）
dora-log-utils~11日志解析工具
dora-message~36通用类型、WS 协议、节点/数据 ID、元数据、鉴权令牌
ros2-bridge~30ROS2 消息/服务/动作解析

运行单个 crate 的测试：

cargo test -p dora-cli
cargo test -p dora-core
cargo test -p dora-arrow-convert

CLI 测试

CLI 测试在不运行任何命令的情况下验证命令解析、参数校验和值解析器，位于 CLI crate 内的 #[cfg(test)] 模块中。

测试内容：

  • Clap 模式校验（Args::command().debug_assert()）
  • 每个子命令的解析（run、up、down、start、stop、list、logs、build、graph、new、status、inspect top、topic list/hz/echo、node list）
  • 拒绝未知子命令
  • --help 和 --version 的退出码
  • 值解析器：parse_store_spec（协调器存储后端）、parse_window（topic hz 窗口）
  • 工具函数：parse_version_from_pip_show

运行方式：

cargo test -p dora-cli

如何添加新测试：

添加新的 CLI 子命令或值解析器时，请在同一文件的 #[cfg(test)] 模块中添加相应测试。对于子命令解析，请在 binaries/cli/src/command/mod.rs 中添加一个 parse_ok 调用。对于值解析器，请在定义该解析函数的文件中添加测试。

集成测试（节点 I/O）

文件：tests/example-tests.rs

这些测试使用预先录制的输入运行编译好的节点可执行文件，并将输出与预期基线进行比对。无需协调器或守护进程。

cargo test --test example-tests

工作原理：

  1. 构建并运行一个节点 crate（例如 rust-dataflow-example-node）
  2. 将 DORA_TEST_WITH_INPUTS 设置为一个带有定时事件的 JSON 文件
  3. 设置 DORA_TEST_NO_OUTPUT_TIME_OFFSET=1 以获得确定性输出
  4. 将 JSONL 输出与 tests/sample-inputs/expected-outputs-*.jsonl 进行比对

示例输入/输出文件位于 tests/sample-inputs/。

Smoke 测试

文件：tests/example-smoke.rs

每个适用示例都会测试两种执行模式：

  • 联网（Networked）（dora up + dora start --detach + 轮询 + dora stop + dora down）：测试完整的协调器/守护进程 WS 控制平面。
  • 本地（Local）（dora run --stop-after）：在单进程内运行所有内容，测试单进程数据流路径。
# Must run single-threaded (shared coordinator port)
cargo test --test example-smoke -- --test-threads=1

# Run only networked or local tests
cargo test --test example-smoke smoke_rust -- --test-threads=1
cargo test --test example-smoke smoke_local -- --test-threads=1

也提供了一个 bash 脚本用于快速本地验证：

./scripts/smoke-all.sh              # all examples
./scripts/smoke-all.sh --rust-only  # Rust examples only
./scripts/smoke-all.sh --python-only # Python examples only

E2E 测试（WebSocket CLI）

文件：tests/ws-cli-e2e.rs

分两组：

未忽略（快速）： 启动一个进程内协调器，直接测试 WsSession：

cargo test --test ws-cli-e2e
  • cli_list_empty——空数据流列表
  • cli_status_no_daemon——守护进程连通性检查
  • cli_stop_nonexistent——缺失数据流的错误处理
  • cli_multiple_requests_same_session——会话复用

已忽略（完整栈）： 使用 dora up 配合真实节点：

cargo test --test ws-cli-e2e -- --ignored --test-threads=1
  • e2e_start_list_stop——启动、列出、停止的生命周期
  • e2e_sequential_dataflows——依次运行两个数据流

容错测试

文件：tests/fault-tolerance-e2e.rs

这些测试直接使用 Daemon::run_dataflow（无需 CLI）来测试重启策略和输入超时。

cargo test --test fault-tolerance-e2e

测试项：

  • restart_recovers_from_failure——设置了 restart_policy: on-failure 的节点在崩溃后仍能存活（15 秒）
  • max_restarts_limit_reached——节点耗尽 max_restarts: 2 的额度（15 秒）
  • input_timeout_delivers_input_closed_to_downstream——input_timeout: 0.5s 在上游静默后触发，向观察者投递 InputClosed（5 秒）

这些测试的 Dataflow YAML 位于 tests/dataflows/。

协调器集成测试

文件：binaries/coordinator/tests/ws_control_tests.rs、binaries/coordinator/tests/ws_daemon_tests.rs

这些测试会启动一个进程内的协调器，测试 WebSocket 控制平面与守护进程平面。

cargo test -p dora-coordinator

覆盖的内容：健康检查、list/stop/destroy 请求、无效的 JSON/参数、并发请求、ping/pong、守护进程注册、断开连接清理、错误净化（不泄露内部调用链）、artifact store 在 drop 时的清理。

CI 流水线

CI 在推送/PR 到 main 时运行。参见 .github/workflows/ci.yml。

fmt  ──────────────┐
clippy ────────────┤ (all run in parallel)
test ──────────────┤
typos ─────────────┘
                   │
              e2e (depends on test)
作业（Job）Runner运行内容
fmtubuntu-latestcargo fmt --all -- --check
clippyubuntu-latestcargo clippy --all ... -- -D warnings
testubuntu-latestcargo test --all ...（不含 Python 与 dora-examples）
e2eubuntu-latest示例测试、容错测试、冒烟测试、WS 端到端测试
typosubuntu-latestcrate-ci/typos@master

e2e 作业仅在 test 通过后才运行。其他所有作业并行运行。

编写新测试

单元测试

在待测代码所在的同一文件中添加一个 #[cfg(test)] 模块：

#![allow(unused)]
fn main() {
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parses_valid_input() {
        let result = parse("valid");
        assert_eq!(result, expected);
    }
}
}

节点的集成测试

使用 dora-node-api 中的集成测试框架。有三种方式：

1. setup_integration_testing（推荐）

在节点的 main 函数之前调用，用于注入输入并捕获输出：

#![allow(unused)]
fn main() {
#[test]
fn test_main_function() -> eyre::Result<()> {
    let events = vec![
        TimedIncomingEvent {
            time_offset_secs: 0.01,
            event: IncomingEvent::Input {
                id: "tick".into(),
                metadata: None,
                data: None,
            },
        },
        TimedIncomingEvent {
            time_offset_secs: 0.055,
            event: IncomingEvent::Stop,
        },
    ];
    let inputs = TestingInput::Input(
        IntegrationTestInput::new("node_id".parse().unwrap(), events),
    );
    let (tx, mut rx) = integration_testing::unbounded_channel();
    let outputs = TestingOutput::ToChannel(tx);
    let options = TestingOptions { skip_output_time_offsets: true };

    integration_testing::setup_integration_testing(inputs, outputs, options);
    crate::main()?;

    let outputs = integration_testing::drain_outputs(&mut rx);
    assert_eq!(outputs, expected_outputs);
    Ok(())
}
}

2. 环境变量模式

直接测试编译出来的可执行文件，最接近生产环境的行为：

DORA_TEST_WITH_INPUTS=path/to/inputs.json \
DORA_TEST_NO_OUTPUT_TIME_OFFSET=1 \
DORA_TEST_WRITE_OUTPUTS_TO=/tmp/out.jsonl \
cargo run -p my-node

3. DoraNode::init_testing

用于在不经过 main 的情况下测试节点逻辑：

#![allow(unused)]
fn main() {
let (node, events) = DoraNode::init_testing(inputs, outputs, Default::default())?;
}

生成测试输入文件

通过设置 DORA_WRITE_EVENTS_TO 来录制真实的数据流事件：

DORA_WRITE_EVENTS_TO=/tmp/recorded-events dora run examples/rust-dataflow/dataflow.yml

这会写出 inputs-{node_id}.json 文件，可直接配合 DORA_TEST_WITH_INPUTS 使用。

工作区级别的集成测试

在 tests/ 目录中添加新的测试文件。对于需要完整 CLI 栈的测试，请遵循 tests/example-smoke.rs 中的模式：

网络模式（涉及协调器 + 守护进程）：

  1. 用 Once 守卫来构建节点（避免每次测试都重新构建）
  2. 用 dora down 清理残留进程
  3. 用 dora up 启动集群
  4. 用 dora start --detach 运行数据流
  5. 通过轮询 dora list --format json 判断是否完成
  6. 用 dora stop --all 和 dora down 清理

本地模式（单进程，进程内协调器）：

  1. 用 Once 守卫构建 CLI
  2. 运行 dora run <yaml> --stop-after <duration>
  3. 断言退出码为成功

约定

  • 使用 assert2::assert! 以获得更友好的错误信息（作为 dev-dependency 可用）
  • 临时输出文件使用 tempfile::NamedTempFile
  • 需要独占端口访问的端到端测试应标记为 #[ignore]，并以 --test-threads=1 方式运行
  • 异步测试使用 #[tokio::test(flavor = "multi_thread")]
  • 容错测试的数据流放在 tests/dataflows/ 中
  • 示例输入/输出基线放在 tests/sample-inputs/ 中

故障排查

cargo test 无法编译 Python 包

始终排除 Python 包：

cargo test --all \
  --exclude dora-runtime-python \
  --exclude dora-node-api-python \
  --exclude dora-operator-api-python \
  --exclude dora-ros2-bridge-python

冒烟测试/端到端测试因“地址已被占用”而失败

有残留的协调器或守护进程仍在运行。请清理：

dora down
# or kill processes manually:
pkill -f dora-coordinator
pkill -f dora-daemon

冒烟测试挂起或超时

  • 如果机器较慢，可增大测试中的超时时间（查找 Duration::from_secs(...)）
  • 检查示例节点是否能成功构建：
    cargo build -p rust-dataflow-example-node -p rust-dataflow-example-status-node \
  -p rust-dataflow-example-sink -p rust-dataflow-example-sink-dynamic
cargo build -p log-sink-file -p log-sink-alert -p log-sink-tcp
cargo build --release -p benchmark-example-node -p benchmark-example-sink
  • 对于 Python 冒烟测试，请确认已安装 pyarrow 和 numpy

端到端测试并行运行时失败

冒烟测试和被忽略的端到端测试必须以单线程方式运行：

cargo test --test example-smoke -- --test-threads=1
cargo test --test ws-cli-e2e -- --ignored --test-threads=1

集成测试输出与预期不符

  1. 检查是否已设置 DORA_TEST_NO_OUTPUT_TIME_OFFSET=1（不同机器上的时间偏移会有差异）
  2. 如果节点的行为是有意更改的，请重新生成基线：
    DORA_TEST_WITH_INPUTS=tests/sample-inputs/inputs-rust-node.json \
DORA_TEST_NO_OUTPUT_TIME_OFFSET=1 \
DORA_TEST_WRITE_OUTPUTS_TO=tests/sample-inputs/expected-outputs-rust-node.jsonl \
cargo run -p rust-dataflow-example-node

拼写检查（typos）失败

typos 的配置位于 _typos.toml。要添加误报排除项：

[default.extend-identifiers]
MyCustomIdent = "MyCustomIdent"

测试本地通过但在 CI 中失败

  • CI 运行在 Ubuntu 上；请检查是否存在平台相关的假设（路径、进程信号）
  • CI 使用 rust-cache，因此依赖版本可能与你本地的 lockfile 不同
  • 确认 cargo fmt --all -- --check 能通过（CI 会强制检查这一点）
